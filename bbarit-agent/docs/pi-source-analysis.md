# Pi Agent Source Analysis

This Rust port follows the Pi source layout and behavior boundaries below.

## Source Areas

- `packages/ai/src/providers/*.ts`: provider factories. Each provider defines `id`, display `name`, `baseUrl`, auth source, model list, and API adapter.
- `packages/ai/src/providers/*.models.ts`: generated model catalog. This is the source of truth for built-in model IDs, API type, base URL, reasoning support, context window, and max tokens.
- `packages/ai/src/models.ts`: provider registry abstraction. It stores providers, resolves auth, and dispatches calls to the provider-owned stream implementation.
- `packages/ai/src/env-api-keys.ts`: environment variable mapping for API key auth, plus ambient credential detection for Vertex and Bedrock.
- `packages/coding-agent/src/core/auth-storage.ts`: `auth.json` credential priority, stored API keys, OAuth access tokens, and refresh orchestration.
- `packages/coding-agent/src/config.ts`: Pi config directories: project `./.pi`, user `~/.pi/agent`, `PI_CODING_AGENT_DIR`, and `PI_CODING_AGENT_SESSION_DIR`.
- `packages/coding-agent/src/core/model-resolver.ts`: model matching, provider defaults, scoped favorites, glob/fuzzy matching, and `:<thinking>` suffix parsing.
- `packages/coding-agent/src/core/session-manager.ts`: JSONL session format, tree entries, migration, branch navigation, labels, compaction entries, and session info.
- `packages/coding-agent/src/core/agent-session.ts`: runtime orchestration over agent messages, model changes, thinking level, tools, bash execution, compaction, session switching, and extension hooks.
- `packages/coding-agent/src/core/tools/*`: built-in tools: `read`, `bash`, `edit`, `write`, `grep`, `find`, `ls`.
- `packages/coding-agent/src/core/settings-manager.ts`: global/project settings merge and runtime preferences.
- `packages/coding-agent/src/core/resource-loader.ts`: extensions, skills, prompt templates, themes, and `AGENTS.md`/`CLAUDE.md` context file loading.
- `packages/coding-agent/src/core/prompt-templates.ts`: markdown prompt template loading, frontmatter descriptions, and shell-style argument substitution.
- `packages/coding-agent/src/core/skills.ts`: Agent Skills `SKILL.md` discovery, frontmatter metadata, and prompt formatting.

## Rust Port Mapping

- `src/providers/catalog.rs`: generated from Pi provider factories and model catalog, with Pi's documented local OpenAI-compatible Ollama path promoted to a built-in provider for CUI selection. Current import includes built-in Ollama fallback models and runtime discovery from `OLLAMA_HOST`/`OLLAMA_BASE_URL` via `/api/tags`.
- `src/providers/metadata.rs`: generated from Pi model metadata for per-model `thinkingLevelMap` and selected `compat` fields such as `thinkingFormat`, `supportsReasoningEffort`, and `forceAdaptiveThinking`.
- `src/providers/registry.rs`: Pi-style provider/model registry plus `models.json` custom provider loading, extension `pi.registerProvider()` provider/model loading, extension `pi.unregisterProvider()` provider/model removal, provider/model request config for extension `headers` and `authHeader`, provider overrides, custom providers/models, `modelOverrides`, `:<thinking>` suffix parsing, model thinking-level clamping, built-in Ollama local-model discovery, and GitHub Copilot OAuth model filtering/baseUrl rewriting from stored credentials.
- `src/config.rs`: Pi-compatible config lookup for project `./.pi`, user `~/.pi/agent`, legacy `./.bbarit-agent`, session directory env vars, `~` expansion for configured/env/CLI paths, lexical path normalization, project-trust-gated project settings/resource loading with `defaultProjectTrust`, `--approve`/`-a`, `--no-approve`/`-na`, scope-relative resource/package path resolution (`~/.pi/agent` for global settings and project `.pi` for project settings), BOM-tolerant `settings.json`, `packages` local path entries and package filter objects including package `themes`, CLI tool filters (`--no-tools`, `--no-builtin-tools`, `--tools`, `--exclude-tools`), Pi resource CLI filters (`--extension`/`-e`, `--no-extensions`/`-ne`, `--skill`, `--no-skills`/`-ns`, `--prompt-template`, `--no-prompt-templates`/`-np`, `--theme`, `--no-themes`, `--no-context-files`/`-nc`), `defaultThinkingLevel`, `systemPrompt`/`appendSystemPrompt` file-or-text resolution, trust-gated `.pi/SYSTEM.md` and `.pi/APPEND_SYSTEM.md` discovery with global `~/.pi/agent` fallback, explicit extension/prompt/skill paths, legacy `skills.customDirectories`/`skills.enableSkillCommands` migration, `enableSkillCommands`, `shellPath`, and `shellCommandPrefix`.
- `src/auth.rs`: Pi-compatible `auth.json` reader/writer for stored `api_key` credentials including provider `env` overlays, OAuth `access` credentials, automatic expired-token refresh/write-back for built-in OAuth providers, restricted auth-file writes on Unix, browser login for `anthropic`, Codex `accountId` preservation, browser/device login for `openai-codex`, device login for `github-copilot`, and Copilot account-specific model metadata.
- `src/llm.rs`: API dispatch by Pi `api` value. Implemented: `openai-responses`, `azure-openai-responses`, `openai-codex-responses`, `openai-completions`, `mistral-conversations`, `anthropic-messages`, `google-generative-ai`, `google-vertex`, and non-streaming `bedrock-converse-stream` via Bedrock Converse + SigV4. Tool declarations, tool-call extraction, assistant tool calls, provider-native tool results, Cloudflare AI Gateway auth headers, extension custom provider `headers`/`authHeader` for OpenAI-compatible/Mistral/Anthropic requests, extension `pi.registerProvider(... streamSimple)` custom provider completions, Azure OpenAI resource/base URL/deployment-name env resolution, Google Vertex API-key or ADC bearer-token transport, Pi-style thinking/reasoning payloads with provider-specific map/format handling, response usage parsing for token accounting, and `{ENV_VAR}` baseUrl template resolution from environment or stored auth `env` overlays are wired for these APIs. Registered but not fully implemented yet: remaining browser OAuth provider flows and full AWS SDK ambient credential chain.
- `src/session.rs`: JSONL tree session with `parent_id`, `current_node`, model changes including `thinkingLevel`, per-assistant-message token usage, branching, compaction entries, session metadata, lazy session-file creation, session listing/resume/new/fork/clone support, exact `--session-id` open-or-create, deterministic ephemeral ids for `--no-session --session-id`, CLI `--fork <path|id>`, `/export [path]` HTML-default or `.jsonl` branch export, `/import <path.jsonl>` JSONL import and resume, label entries via `/label`, self-contained HTML export, and `/share` default shareable history HTML generation.
- `src/tools.rs`: built-in `read`, `bash`, `edit`, `write`, `grep`, `find`, `ls` executors and JSON tool schemas. `bash` runs in the resolved project cwd, and the Rust tools accept Pi-compatible argument aliases such as `file_path`, `start_line`/`end_line`, `old_string`/`new_string`, `glob`, `ignoreCase`, `context`, and `limit`; unit tests cover these compatibility paths.
- `src/extensions.rs`: Pi-style local extension loader. Discovers `extension.json`, `pi-extension.json`, or `package.json` with `piAgent` under user/project `extensions` directories, explicit `settings.json` `extensions` paths, and local `settings.packages` package manifests/conventional extension directories; exposes extension `prompts`/`skills`/`themes` resource folders, runs `resources_discover`, detects Pi `ExtensionAPI.on(...)` lifecycle hook names from manifest metadata or TS/JS source, runs JS/TS runtime commands/tools/hooks/shortcuts/provider `streamSimple` handlers through the Node extension wrapper with jiti/TypeScript/fallback transpilation, returns mutated hook payloads for Pi-style mutable events, provides a CUI-compatible `ctx.ui` surface for notify/status/widget/title/working/editor/tools/dialog/custom calls, carries extension tool `promptSnippet`/`promptGuidelines` into RPC introspection and provider system prompts, and collects runtime `pi.registerProvider()`/`pi.unregisterProvider()` provider changes for the provider registry.
- `src/commands.rs`: CUI commands corresponding to Pi slash commands and an iterative assistant -&gt; tool call -&gt; tool result loop. Includes `/auth` to inspect Pi-compatible credential stores without printing secrets, `/thinking` for Pi-style reasoning level control, `/login <provider> api-key <key> ENV=VALUE...` for provider env overlays such as Cloudflare account/gateway IDs, `/session` file/id/message/model/token/cost status with actual and model-grouped usage when providers return usage, `/sessions`/`/new`/`/resume`/`/fork`/`/clone`/`/name` plus `/export`/`/import`/`/share` for Pi-style session runtime actions and shareable history, `/reload` with live prompt/skill/theme/extension/hotkey counts, `/changelog` and `/quit` from Pi's built-in slash command list, `/trust` for project trust storage, `shellPath` and `shellCommandPrefix` wrapping for bash execution, `!` bash execution that records tool output and `!!` bash execution outside LLM context, Pi-style `--no-builtin-tools`/`--tools`/`--exclude-tools` behavior across built-in and extension tools, extension/custom tool precedence over built-ins for same-name calls, Pi-style `tool_call` hooks that can mutate tool arguments or block execution before the tool runs, terminating extension tool results via `terminate: true` that skip the automatic follow-up LLM turn when the whole tool batch terminates, Pi-style `tool_result` hooks that can rewrite text content and `isError` before result persistence/follow-up, and `/extensions`/`/extension`/`/x`/`/shortcut` for local extension discovery and execution.
- `src/rpc.rs`: Pi-style `--mode rpc` JSONL process protocol over stdin/stdout. Implemented commands include `prompt`, `get_state`, `get_messages`, `set_model`, `cycle_model`, `get_available_models`, thinking level controls, queue mode settings, manual compaction events, bash execution, session stats, HTML export, session switching/new/fork/clone/name, fork-message listing, last-assistant-text lookup, `get_commands` for extension/prompt/skill commands, `get_extensions` for extension commands/hooks metadata, `get_available_tools`/`run_extension_tool`, `run_extension_hook`, `run_extension_shortcut`, and `get_themes` for loaded theme resources. The parser accepts strict LF records plus a leading BOM for Windows PowerShell compatibility.
- `src/resources.rs`: Pi-compatible prompt and skill discovery for user/project resource directories, explicit `settings.json` `prompts`/`skills` file or directory paths with Pi-style `!` exclude, `+` force-include, `-` force-exclude, and basic `*`/`?` glob filtering for configured local entries, local `settings.packages` package manifests/conventional prompt and skill directories, project/ancestor/user `.agents/skills` auto-discovery, plus loaded extension resource directories. Resource disable flags suppress discovery while preserving explicit CLI `--skill` and `--prompt-template` paths. Supports `/prompts`, `/prompt`, direct `/<prompt>` template commands, `/skills`, `/skill`, `/skill:name`, frontmatter descriptions, Pi-style prompt argument substitution including defaults and `${@:N}` slices, and Pi-style `<available_skills>` system-prompt skill summaries.
- `src/themes.rs`: Pi-style theme resource discovery for user/project theme directories, extension-provided theme directories, plus explicit `settings.json`/CLI theme paths and package theme filters. It loads JSON themes by `name`, dedupes by name, resolves basic `vars`/`colors` values to ANSI colors, and exposes `/themes`, `/theme <name>`, and RPC `get_themes`.
- `src/cli.rs`: CLI flags modeled after Pi's basic flags: provider/model/thinking/session/session-id/fork/print/resume/continue/models, project trust overrides, tool selection/disable flags, resource discovery flags, `--export <session> [output.html]`, and `--mode text|json|rpc` parsing.
- `src/main.rs`: Pi-style entrypoint routing for text/TUI plus JSONL, RPC, and CLI session export modes. JSON mode emits a session header and turn/message/agent lifecycle events for non-interactive input; RPC mode is routed before stdin prompt expansion so JSONL commands are not consumed as prompt text; `--export` opens a session JSONL reference and writes self-contained HTML.
- `src/package_cli.rs`: Pi-style package command entrypoint for `list`, `install`, `remove`, `uninstall`, and package-oriented `update` settings management. It reads/writes `settings.json` `packages` arrays for user or project scope (`-l`) and honors project trust for project-local package config writes. Local path packages are referenced directly, `git:`/URL packages are cloned under `<scope>/.pi-or-agent/git/<safe-source>` with `@ref` tag/commit checkout for HTTPS, local, and `git@host:path@ref` sources, and `npm:` packages install under `<scope>/.pi-or-agent/npm/node_modules/<name>`; `PI_PACKAGE_DIR` can override the package storage base. `npmCommand` is honored for package-manager operations, including npm package installs and git package dependency installs; git dependencies use `install --omit=dev` by default and plain `install` when `npmCommand` is configured, matching Pi wrapper compatibility. `update --extensions`, `update --all`, and `update <source>` reconcile configured git/npm package installs without moving pinned git refs. Git package dependencies are installed with npm only when runtime dependency fields are present, so dependency-free packages work in minimal environments.
- `src/trust.rs`: Pi-style project trust store at `~/.pi/agent/trust.json`, including nearest-ancestor trust lookup, effective trust reporting, project resource detection for `.pi` and `.agents/skills` resources, and enforcement hooks for dangerous project actions.
- `src/tui.rs`: Initial Rust TUI layer for interactive mode. It renders session/model/head state, token totals and last model usage, recent conversation, command output, command hints, a model selector, and a direct `/ollama` local-model selector; `--tui` forces it for smoke testing and `--no-tui` keeps the previous plain prompt. Loaded theme colors are applied to core frame/label/output elements through ANSI truecolor/256-color sequences, while Pi's full component-level theme surface remains larger than this Rust port.

## Known Gaps From Full Pi

- OAuth browser login flows are partially ported. `anthropic` supports Pi-style browser login; `openai-codex` supports Pi-style browser login plus device-code login; `github-copilot` supports device-code login. Stored `auth.json` API keys and OAuth access tokens are read. Expired OAuth credentials are refreshed and written back for `anthropic`, `openai-codex`, and `github-copilot`, with OpenAI Codex refresh preserving the required ChatGPT account id.
- Amazon Bedrock Converse is implemented for `AWS_ACCESS_KEY_ID`/`AWS_SECRET_ACCESS_KEY`/optional `AWS_SESSION_TOKEN`, `AWS_PROFILE` from `~/.aws/credentials` plus region from `~/.aws/config`, and `AWS_BEARER_TOKEN_BEDROCK`. Full AWS SDK credential chain parity (ECS, web identity, SSO/process credentials) is not ported yet.
- Google Vertex supports API-key REST calls with `GOOGLE_CLOUD_API_KEY`, plus ADC-style bearer-token calls via `GOOGLE_OAUTH_ACCESS_TOKEN`, `GOOGLE_VERTEX_ACCESS_TOKEN`, or `gcloud auth application-default print-access-token`. It requires `GOOGLE_CLOUD_PROJECT` or `GCLOUD_PROJECT`, and `GOOGLE_CLOUD_LOCATION`.
- Local extension discovery is implemented for manifest commands, runtime commands/tools/hooks/shortcuts, runtime provider registrations/removals with custom headers/authHeader and `streamSimple` completion handlers, CUI-compatible extension UI calls, extension resource directories, local package manifest/conventional resources, and static Pi hook metadata discovery. Project trust storage, status commands, interactive trust prompts, and trust enforcement for shell/write/edit/extension-shell/agent-tool execution are implemented. Package CLI settings add/list/remove plus basic `git:` and `npm:` install/remove/update storage is implemented, while remaining full Pi extension/package parity gaps are npm version lookup precision, npm uninstall/root lookup parity, richer git URL identity/dedupe, concurrent/background startup installs, true interactive extension UI request/response bridging, dynamic post-start provider refresh parity, custom extension OAuth provider hooks, and remote share upload.
- `--mode json` and `--mode rpc` now both emit JSONL lifecycle events around the Rust command/agent path. Remaining event parity gaps are provider streaming deltas, granular tool execution start/update events, true asynchronous steering/follow-up queues, extension UI request/response bridging, automatic compaction/retry parity, and exact Pi message-shape compatibility for every event.
- Provider-specific advanced compatibility options are cataloged partially; `thinkingLevelMap`, `thinkingFormat`, `supportsReasoningEffort`, and `forceAdaptiveThinking` are imported, while cache-control/routing/header-specific compat details are still not fully ported.
