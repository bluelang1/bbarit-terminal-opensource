# 텔레그램 설정 화면 복구 설계

상태: 설계 2차 (소유자 답변 반영). **구현 보류** — 진행 중인 다른 큰 작업이 머지된 뒤 시작한다.
작성일 2026-11-23.

## 왜 하는가

집 밖에서 휴대폰으로 터미널 상황을 보고, Claude 탭에 지시를 보내고 싶다. 앱에는 그 일을 하는
텔레그램 연동 코드가 이미 있는데, 켜고 설정할 화면이 없어서 쓸 수 없다.

비서 게이트웨이(설정 → 채널)는 대안이 되지 못한다. 외부에서 쓰려면 Cloudflare 터널을 따로 켜야
하고, 비서는 터미널에 직접 입력하지 못하게 막혀 있다. 텔레그램 방식은 앱이 텔레그램 서버에 물어
보는 구조라 내 컴퓨터로 들어오는 주소가 생기지 않고, 휴대폰 알림도 온다.

## 화면을 되살리기 전에 고쳐야 하는 것

화면만 다시 붙이면 아래 문제가 그대로 사용자에게 열린다. 그래서 이 설계는 화면보다 이것들을 먼저 한다.

1. **등록 안 된 채팅도 명령을 내릴 수 있다.** 원격 제어가 켜져 있으면, 봇 이름을 아는 누구나
   `/projects` 로 프로젝트 목록을 보고 `/project <이름> shell` 로 새 터미널을 만들어 자기 채팅에
   연결할 수 있다(`src/App.tsx` 9705-9747). 그 뒤에는 그 터미널에 명령을 넣을 수 있다. 지금 방어는
   "원격 제어 기본 꺼짐" 하나뿐이다.
2. **그룹 채팅에서는 보낸 사람을 확인하지 않는다.** 채팅 ID 만 맞으면 그 그룹의 누구나 실행한다.
   Rust 가 넘기는 수신 항목에 보낸 사람 ID 가 아예 없다(`main.rs` 2612-2660).
3. **출력 미러링은 비밀을 가리지 않는다.** `redactSecrets` 는 명령 미러에만 걸려 있고
   (`remoteMirror.ts` 299), 화면 출력에는 걸려 있지 않다(같은 파일 192). `cat .env` 를 치면 내용이
   그대로 텔레그램 서버로 나간다.
4. **토큰 저장 위치가 두 군데로 갈린다.** 화면에서 저장한 토큰은 앱 DB(`~/.config/octo/bbarit.db`)
   에 평문으로 들어가고, Rust 의 폴백은 환경변수와 `~/.config/octo/.env` 만 본다(`main.rs` 1720).
   지금 흐름은 프런트가 토큰을 인자로 넘기므로 동작에는 문제가 없지만, 화면 문구가 저장 위치를
   정확히 말해야 한다.

## 목표

- 설정에서 텔레그램을 처음부터 끝까지 설정할 수 있다: 봇 토큰 → 채팅 연결 → 테스트 → 켜기.
- 켜고 끄는 값 5개를 화면에서 바꿀 수 있다: 활성화, 명령어 미러링, 출력 미러링, 원격 제어,
  탭에 텔레그램 버튼 표시.
- 허용 목록에 있는 채팅만 명령을 내릴 수 있다. 그 외 채팅은 어떤 명령도 처리되지 않는다.
- 화면 출력 미러링에도 비밀 가림이 적용된다.
- 디스코드·슬랙 화면이 나중에 같은 자리에 같은 모양으로 들어올 수 있다.

## 하지 않는 것

- 디스코드·슬랙 설정 화면 (다음 작업. 자리만 잡아 둔다).
- 토큰을 macOS 키체인에 넣기 (지금은 평문 저장이라고 화면에 적는다).
- 웹훅 방식, 여러 봇, 사진·파일 전송.
- 수신 명령 문법 변경 (`!help`, `/keys`, Ctrl+C·Esc·Enter 버튼 등은 그대로 둔다).

## 실패로 보는 것

- 화면은 생겼는데 등록 안 된 채팅이 여전히 터미널을 만들 수 있는 경우.
- 사용자가 모르는 사이에 원격 제어가 켜지는 경우 (업데이트 후 자동으로 켜짐 포함).
- 설정 화면을 여는 것만으로 느려지는 경우 (5000줄짜리 `SettingsPanel.tsx` 에 상태를 더 얹는 것).

## 접근 방식

어디에 둘지 세 가지를 봤다.

1. **독립 "텔레그램" 탭.** 타입에 이미 있어 원래 모양에 가장 가까워 보인다. 디스코드·슬랙이 오면
   탭이 3개 늘어 탭 줄이 길어진다.
2. **"에이전트" 탭 안의 항목.** 문구 키가 `settings.agent.telegram.*` 이라 원래 여기 있었을 가능성이
   높다. 에이전트 탭은 이미 두 블록(2804, 3413행)으로 길어서 찾기 어렵다.
3. **"비서" 탭에 넣기 (채택).** 코드에서는 이 탭의 이름이 `channels` 이고, 한국어 화면에는
   **"비서"** 로 보인다 (`src/i18n/ko.ts` 15-16: "비서 (외부 접속 · QR · 비밀번호)"). 지금 이 탭에는
   비서 게이트웨이 하나만 있다. 이 탭을 "휴대폰·외부에서 앱에 닿는 방법" 을 모으는 곳으로 삼아
   위에서부터 텔레그램 → (나중에) 디스코드·슬랙 → 비서 게이트웨이 순으로 놓는다.

3번으로 정했다 (소유자 결정). 이 탭은 화면에 `channels` 라는 글자로는 나오지 않는다. 앱 언어가
영어면 **"Secretary"**, 한국어면 **"비서"** 로 보이고, 설정 왼쪽 목록에서 "Broker" 와 "Web Terminal"
사이에 있다 (`src/i18n/en.ts` 13-14, `SettingsPanel.tsx` 1911-1913).

탭 이름이 "Secretary / 비서" 인 채로는 텔레그램이 여기 있다는 것을 알 수 없으므로 이름을 바꾼다
(소유자 결정).

| 언어 | 탭 이름 | 설명(마우스를 올리면 보이는 글) |
|---|---|---|
| 한국어 | 원격 | 원격 (텔레그램 · 비서 · 외부 접속) |
| 영어와 나머지 6개 언어 | Remote | Remote (Telegram · Secretary · External access) |

`settings.tab.channels`, `settings.tab.channelsTitle` 두 키를 8개 언어 파일에서 함께 고친다. 지금도
한국어 외 7개 언어는 영어 문구를 쓰고 있다.

코드 구조는 한 가지로 정한다. `SettingsPanel.tsx` 에 다시 그려 넣지 않고 새 구성요소
`src/components/settings/TelegramSettings.tsx` 로 뺀다. 지금 `SettingsPanel.tsx` 에 죽어 있는 텔레그램
상태·함수(토큰, 마법사, 통계, 채팅 목록)는 이 파일로 옮기고 원래 자리에서는 지운다.

## 화면

"원격" 탭(지금의 "비서" 탭) 맨 위에 "텔레그램" 묶음이 생긴다. 상태에 따라 두 모양이다.

토큰이 없을 때 (설정 마법사, 문구는 기존 `settings.agent.telegram.step1~4`, `guide1~4` 를 쓴다):

```
│ 1단계. 텔레그램 봇 만들기                                  │

│  · /newbot 명령을 보내세요. …                              │
│                              [BotFather 열기]   [다음]     │
└──────────────────────────────────────────────────────────┘
2단계  봇 토큰 [••••••••••••] [표시] [검증 후 저장]
3단계  봇에게 아무 메시지나 보내세요          [채팅 감지]

```

```
허용된 채팅                                              [새 채팅 감지]
  홍길동 (개인)   12345     [✓] 명령 허용                        [테스트] [연결 해제]
  팀방 (그룹)    -100987    [ ] 명령 허용   보낸 사람: 홍길동만   [테스트] [연결 해제]

프로젝트별 기본 채팅
  bbarit-terminal   [ 12345 ▾ ]
  cgs-backend       [ 없음  ▾ ]
```

동작 규칙:

- **원격 제어를 켤 때**만 확인 창을 띄운다. 내용: 허용된 채팅이 터미널에 명령을 넣을 수 있다는 것,
  봇 토큰이나 채팅방이 뚫리면 남이 내 컴퓨터에서 명령을 실행할 수 있다는 것. 허용된 채팅이 0개면
  스위치를 켤 수 없고 이유를 옆에 적는다.
- **활성화가 꺼져 있으면** 나머지 스위치는 흐리게 보이고 값은 유지한다.
- 토큰을 지우면 활성화와 원격 제어를 함께 끈다.
- 프로젝트별 기본 채팅 선택지는 허용된 채팅 목록에서만 고른다.
- 다른 프로그램이 같은 토큰을 쓰는 경우(HTTP 409)에는 기존 문구 `app.telegram.conflict409` 를 묶음
  위에 띄운다.
- 설정 화면을 여는 것만으로 네트워크를 부르지 않는다. 지금은 패널이 열릴 때 `tgPingTest` 가 돈다
  (`SettingsPanel.tsx` 1417). "원격" 탭이 보일 때, 토큰이 있을 때만 한 번 부른다.

## 허용 목록 (보안)

값 두 개를 새로 둔다. 기본은 빈 배열과 꺼짐이다.

- `agent.telegramAllowedChats: { chatId, label, commands: boolean, allowedUserIds? }[]`
- `agent.telegramAllowGroups: boolean`

그룹 채팅은 두 단계로 정한다 (소유자 질문에 대한 답).

- **전체 스위치 "그룹 채팅 허용"**: 꺼져 있으면 그룹 채팅은 등록 자체가 안 되고, 이미 등록된 그룹도
  미러링과 명령이 모두 멈춘다. 그룹을 쓸 생각이 없는 사람은 이것 하나로 끝난다.
- **채팅별 "명령 허용"**: 채팅은 어차피 하나씩 등록하므로, 등록된 줄마다 "이 채팅이 명령을 내릴 수
  있는가" 를 따로 켠다. 개인 채팅과 그룹 모두에 있다. 꺼져 있으면 그 채팅은 미러링만 받는다.
  개인 채팅은 등록할 때 켜진 상태로, 그룹은 꺼진 상태로 들어간다.
- 채팅별로 "그룹 허용" 을 또 두지는 않는다. 그룹을 등록하는 행위가 곧 그 그룹을 허용하는 것이다.

- 채팅이 허용 목록에 들어가는 길은 설정 화면(감지 → "이 채팅 사용", 또는 Chat ID 직접 입력)과
  탭의 연결 모달 두 가지뿐이다. 채팅 쪽에서 스스로 등록하는 길은 없앤다.
- 폴러는 수신 항목마다 맨 먼저 허용 여부를 본다. 허용되지 않은 채팅이면 아무것도 하지 않고
  답장도 보내지 않는다. `/projects`, `/project`, `/disconnect` 같은 "연결 전 명령" 도 허용된
  채팅에서만 동작한다.
- 허용된 채팅이 `/project <이름>` 으로 새 터미널을 만드는 기능은 남긴다 (밖에서 새 작업을 시작하는
  용도).
- 그룹 채팅은 허용할 때 "보낸 사람 제한" 을 건다. Rust 수신 항목에 보낸 사람 ID 와 이름을 추가하고
  (`TelegramIncoming` 에 `from_id`, `from_name`), 감지 단계에서 메시지를 보낸 사람을
  `allowedUserIds` 에 넣는다. 그룹에서 명령이 통하려면 세 가지가 모두 맞아야 한다: 전체 스위치
  켜짐, 그 채팅의 명령 허용 켜짐, 보낸 사람이 `allowedUserIds` 에 있음.
- 판정은 순수 함수 하나로 뺀다: `src/terminal/telegramAccess.ts` 의
  `isAllowedSender(allowed, allowGroups, chatId, fromId, chatType)`. 폴러는 이 함수만 부른다.
- **기존 사용자 이관**: 이미 `terminal.telegramChatId` 나 `project.telegramChatId` 에 들어 있는 채팅은
  첫 실행 때 허용 목록으로 한 번 옮긴다.
  - 그룹 채팅(음수 ID)은 보낸 사람 제한 없이 옮겨지므로 "미러링만 받고 명령은 못 내리는" 상태가
    된다. 설정 화면의 그 줄에 "보낸 사람을 지정해야 명령을 받을 수 있습니다" 를 띄운다.
  - 이관 시점에 원격 제어가 이미 켜져 있던 경우에만(화면이 없었으므로 설정 파일을 손으로 고친
    사용자) 원격 제어를 한 번 끄고, 설정 화면에 "보안 규칙이 바뀌어 원격 제어를 껐습니다. 허용된
    채팅을 확인하고 다시 켜세요" 를 띄운다. 그 외에는 원격 제어 값을 건드리지 않는다.
    (작성자 판단: 조용히 먹통이 되는 것보다 한 번 다시 켜게 하는 쪽이 안전하다.)

## 출력 가림

`flushRemoteScreen` 이 보내기 직전에 `redactSecrets` 를 거치게 한다(`remoteMirror.ts` 192 부근).
가림은 알려진 이름 패턴(`*_TOKEN`, `*_KEY` 등) 기준이라 모든 비밀을 잡지는 못한다. 그래서 화면의
"출력 미러링" 설명에 "화면에 보이는 내용이 텔레그램 서버를 거칩니다" 를 적는다. 이 변경은
디스코드·슬랙 미러에도 같이 적용된다 (같은 함수를 쓴다).

## 검증

- 자동: `telegramAccess` 판정 (허용/미허용, 개인/그룹, 보낸 사람 제한, 이관), `remoteMirror` 출력 가림,
  `TelegramSettings` 의 스위치가 설정 값을 바꾸는지와 "허용 채팅 0개면 원격 제어 못 켬",
  Rust `parse_telegram_updates` 가 보낸 사람을 채우는지.
- 실기 (개발 앱, 전용 테스트 봇): 마법사 4단계 완주, 테스트 메시지 수신, 출력이 채팅에 오는지,
  허용 채팅에서 보낸 글이 Claude 탭에 입력되는지, 다른 계정으로 같은 봇에 `/projects` 를 보내면
  무응답인지, 권한 승인 대기 중에 일반 글이 거부 회신되는지.
- 릴리스 전 소유자가 개발 앱에서 먼저 확인한다.

## 작업 순서

1. 보안 먼저: 허용 목록 + 보낸 사람 확인 + 출력 가림 (화면 없이도 머지 가능).
2. 화면: `TelegramSettings` 추출과 "원격" 탭 배치, 탭 이름 변경.
3. 실기 확인 후 릴리스.

## 정해진 것과 남은 것

- 정해짐: 놓는 자리는 "Secretary / 비서" 탭이고, 이름을 "Remote / 원격" 으로 바꾼다.
- 정해짐: 그룹 채팅은 설정에서 고른다 (전체 스위치 + 채팅별 명령 허용).
- 남음: 허용된 채팅이 `/project` 로 새 터미널을 만드는 기능을 남길지 (이 문서: 남김).

## 다른 작업과의 관계

구현 보류. 진행 중인 큰 작업과 같은 파일(`App.tsx`, `SettingsPanel.tsx`)을 건드리므로 그 작업이
머지된 뒤 시작한다. 그때 이 문서의 줄 번호 근거는 다시 확인해야 한다. 새 코드는 새 파일
(`TelegramSettings.tsx`, `telegramAccess.ts`)에 두어 겹치는 줄을 줄인다.
